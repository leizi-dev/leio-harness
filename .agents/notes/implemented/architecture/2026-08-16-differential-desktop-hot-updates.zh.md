# Agent Note: Differential desktop hot updates

Status: implemented

[English](2026-08-16-differential-desktop-hot-updates.md) | 中文

## Problem

Windows 自包含 NSIS 安装包较大，是因为它包含完整应用运行时；但只修改几个界面文字的热更新不应重新下载这个安装包。把首次安装包直接当成更新附件，会下载大量未变化内容，还可能超过 GitHub 发行版附件限制。

## Decision

首次安装继续使用 `compression: "store"` 的 NSIS 安装包，以安装速度优先。热更新使用 `scripts/build-desktop-delta.mjs` 生成并签名的 NSIS 差分执行文件。差分包只携带 `resources/app.asar.unpacked` 下发生变化的文件，并在 `resources/app.asar` 内执行等长度版本字段替换；它不包含完整 ASAR 或完整应用目录。现有更新器可以沿用已校验的 NSIS 启动路径，因此带更新器的 1.0.0 客户端可以消费 1.0.1 补丁。

发布清单指向差分附件，而不是首次安装包。差分包必须先应用到上一版本的全新安装目录，再验证安装后的执行程序返回 HTTP 200、包含必要的启动条目、提供已变化的插件行为，并且没有插件加载错误，之后才能发布。

## Alternatives considered

- **把完整 NSIS 安装包作为热更新附件。** 不采用：它会重复下载未变化的运行时文件，不符合文件级热更新要求，并可能超过 GitHub 发行版附件限制。
- **发布完整应用 ZIP。** 不采用：它同样包含不必要的内容，还需要另一套替换协议，而现有更新器已经可以启动经过校验的 NSIS 执行文件。
- **在运行进程内替换插件。** 不采用：这会增加回滚复杂度，并可能留下混合版本运行时；签名的重启时文件补丁在进程边界完成替换，行为更可控。

## Consequences

- 只改文字的版本可以生成 KB 级更新附件，同时首次安装包继续以安装速度为优先。
- 差分包必须列出精确的打包文件，并且必须从紧邻的上一版本已安装目录开始测试；仅测试新版本全新安装不能证明热更新可用。
- `app.asar` 内的其他文件变更需要显式的差分操作。目前脚本只支持桌面包版本标记和 unpacked 目录下的变更文件；其他 ASAR 变更必须先扩展脚本并完成测试。
